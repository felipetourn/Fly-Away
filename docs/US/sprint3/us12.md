## Qué se hizo

El administrador elige una instancia de vuelo y ve su capacidad, los pasajes vendidos y los lugares disponibles, en total y por clase.

- **Qué es la ocupación:** por clase, **vendidos** = pasajes de reservas pagadas (solo compras confirmadas), **disponibles** = el contador del vuelo que usa la venta y **capacidad** = la del avión actual. La US11 garantiza que vendidos + disponibles = capacidad.
- **Backend:** app nueva `reportes` (sin modelos ni migraciones). `reportes/servicios.py` tiene `con_ocupacion(vuelos)`, que anota los vendidos por clase en una sola consulta, y `ocupacion_de(vuelo)`. Endpoint `GET /api/reportes/ocupacion/{id}/`, solo para el administrador. Incluye vuelos cancelados o que ya salieron; un id inexistente o mal escrito da 404.
- **Frontend:** en **Gestión de vuelos**, cada fila tiene un ícono de barras ("Ocupación") que abre `/admin/vuelos/:id/ocupacion`. La pantalla muestra número, fecha, ruta, horarios, avión, estado e id del vuelo. Debajo: capacidad, vendidos, disponibles y % de ocupación, y una barra por clase.
- **Datos de ejemplo:** el `seed` ponía disponibles al azar sin pasajes detrás, así que la ocupación de esos vuelos no sumaba. Ahora cada vuelo de ejemplo trae de 0 a 5 ventas reales (reserva pagada, pasajes y pago aprobado). `seed --regenerar` limpia una base vieja.

## Para la US14 (estado del vuelo desde mostrador)

- Cálculo: `from reportes.servicios import con_ocupacion, ocupacion_de`.
- Componente: `frontend/src/components/OcupacionVuelo.tsx` recibe `{ clases, total }` (tipo `Ocupacion` de `lib/ocupacion.ts`) y solo muestra; no llama a la API.
- El endpoint de la US12 hoy es solo del administrador (`EsAdministrador`). Para el empleado se puede usar otro endpoint o ampliar el permiso.

## Cómo probarlo

1. `cd backend && DATABASE_URL= .venv/bin/python manage.py test reportes`
2. `cd frontend && npm run check && npm run build`
3. En la app: entrar como administrador → **Gestión de vuelos** → ícono de barras de un vuelo. Un vuelo sin ventas muestra 0 vendidos. Después de pagar una reserva de ese vuelo con un pasajero (`4242 4242 4242 4242`), los vendidos suben y los disponibles bajan solo en esa instancia y en esa clase. Un pago rechazado no cambia nada.
