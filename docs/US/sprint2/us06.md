## Qué se hizo

Se implementó el proceso de reserva de pasajes para un pasajero autenticado:
1. **Modelos de datos:** Se crearon los modelos `Reserva` y `Pasaje` en la app `reservas` respetando la definición de [modelo.dbml](../../modelo.dbml) y sus nombres de tablas (`reservas`, `pasajes`).
2. **Reglas de negocio y validación en backend:**
   - La reserva se asocia al pasajero autenticado (`pasajero_id`) y a la instancia particular del vuelo (`vuelo_id`).
   - Selección de clase (`economy` o `primera`) y cantidad de pasajes (entre 1 y 9).
   - Nombre, apellido y DNI obligatorios para cada pasajero, uno por pasaje (`test_exige_los_datos_de_cada_pasajero`).
   - Validación estricta del máximo de 9 pasajes y mínimo de 1 (tanto por constraint de base de datos como por validación de API).
   - Verificación de disponibilidad de asientos previa a la reserva bajo bloqueo concurrente (`select_for_update()`) para evitar condiciones de carrera.
   - Si no hay disponibilidad suficiente o el vuelo no está disponible (cancelado o que ya partió), la operación es rechazada devolviendo un mensaje explicativo con el motivo.
   - Creación de registros individuales en `pasajes` con código único de pasaje, clase, precio congelado al momento de reservar y datos de cada viajero.
   - La reserva queda persistida temporalmente con `estado = 'pendiente'` y no se considera compra confirmada hasta que se concrete el pago (US08).
3. **Integración con pagos (US07 / US08):**
   - `backend/pagos/reservas_mock.py` opera sobre `Reserva` y `Pasaje`; `pagos.reserva_id` es FK a `reservas` y la tabla temporal `reservas_demo` se eliminó (migración `pagos/0004`). Al pagar una reserva creada con tarjeta o Mercado Pago, se confirma la compra y se descuentan los asientos del vuelo en su clase.
4. **Interfaz de usuario:**
   - En el buscador de vuelos (`Vuelos.tsx`), al elegir un vuelo y llegar a "Tu viaje", el botón **"Reservar pasajes"** abre el diálogo de reserva `ModalReserva.tsx`.
   - Permite seleccionar clase, ajustar la cantidad de pasajes (1..9), cargar los datos de los pasajeros (precompletando el primero con los datos del usuario autenticado) y verificar la disponibilidad en tiempo real.
   - Pantalla **"Mis reservas"** (`/reservas`): muestra las reservas reales del pasajero, con su estado (`pendiente` con botón **Pagar**, o `confirmada` con chip verde). Si no tiene reservas, ofrece un estado vacío amigable con acceso directo a buscar vuelos.

## Cómo probarlo

1. **Backend y pruebas automatizadas:**
   ```bash
   cd backend
   .\.venv\Scripts\python manage.py test
   ```
   Deben pasar todos los tests (incluyendo los de `reservas` y su integración con `pagos`).

2. **Frontend:**
   ```bash
   cd frontend
   npm run check
   npm run build
   ```

3. **Flujo completo en la aplicación:**
   - Iniciar backend (`python manage.py runserver`) y frontend (`npm run dev`).
   - Iniciar sesión con un usuario pasajero (ej. `pepe@gmail.com`).
   - En la pantalla de inicio, buscar vuelos (ej. AEP a COR).
   - Elegir un vuelo disponible.
   - En la sección "Tu viaje", presionar **"Reservar pasajes"**.
   - En el modal de reserva:
     - Seleccionar la clase (Economy o Primera).
     - Elegir la cantidad de pasajes (1 a 9). Probar que no permite exceder la disponibilidad ni superar 9.
     - Completar los nombres y DNI de los pasajeros.
     - Presionar **"Confirmar reserva"**.
   - La reserva se crea y redirige automáticamente a `/pagar/:reservaId`.
   - Pagar con una tarjeta de prueba aprobada (`4242 4242 4242 4242`).
   - Comprobar que la compra queda confirmada, la reserva pasa a estado confirmada en **/reservas** y los asientos del vuelo se descuentan.
